# Diseño

`hash_caller_program.py` define un AST finito de expresiones, printf, condicionales y recorrido de buckets/cadenas. Ese mismo AST genera las instrucciones C de `build_hash_main` y las ejecuta después del retorno de la traza TAD. No analiza ni ejecuta código C del usuario.

Los argumentos proceden de celdas de retorno y salida de la traza: bool de buscar/contiene/eliminar/insertar, raíz pública al retorno, struct `caller.stats` y bytes inicializados y terminados del buffer del formatter. El listado conserva cabezas y enlaces publicados, verificándolos contra las celdas del heap de la traza; no convierte el resultado de API en texto. La rama de get ausente no lee ni exige inicialización de output.

`caller_printf.c_printf` interpreta la conversión llamando a la CRT C mediante ctypes: `_snprintf` exportado por MSVCRT en Windows y `snprintf` de la libc del proceso en Unix. El nombre C17 snprintf no está exportado como función en la UCRT de este entorno. Se usan varargs tipadas (`int`, `double` promovido, `char *`), buffers acotados y formatos constantes permitidos; no hay compilación runtime, formato numérico Python, cambio global de locale ni llamada al shell. `%n`, formatos desconocidos, NUL, argumentos ausentes/sobrantes y enteros fuera de int32 fallan explícitamente. El oráculo C17 comprueba las conversiones utilizadas por Hash, sin afirmar compatibilidad universal entre CRTs, locales, exponentes o formatos no usados. La imagen Linux requiere una libc que exporte snprintf; Python slim dispone de esa interfaz, pero esta sesión sólo ejecuta Windows.

Cada paso original conserva stdout vacío hasta el retorno real del TAD/formatter. Cada printf del AST agrega un fragmento y un snapshot `step.console_stdout`, con `source_role=caller`, función main y `line_index=-1`; no se atribuye al archivo TAD ni se resalta una línea C/H ajena. El journal guarda bytes auténticos de las nuevas llamadas y reconstruye entradas antiguas mediante el mismo servicio. Devuelve `console_prefix`, `trace.console_prefix` y `console_output`; GET publica `model.console_output`.

El printf `state:...` del epílogo sólo se ejecuta al terminar el main independiente. No se repite por cada operación interactiva. El oráculo compara stdout nativo con journal completo más ese epílogo. clear/destroy siguen siendo void sin mensajes nuevos. Inyección de fallo QA no presente en main no produce una salida que aparente estar reproducida por ese main.
