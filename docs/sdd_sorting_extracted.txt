SDD — Módulo 5: Métodos de Ordenamiento
1. Información general del proyecto
Nombre del proyecto: Visualizador Web de Estructuras de Datos
Módulo: Métodos de Ordenamiento
Versión: 0.1.0
Estado: Especificación inicial para implementación del nuevo módulo
Tecnologías: Python, Flask, HTML5, CSS3, JavaScript, Jinja2, C didáctico
Tipo de proyecto: Aplicación web didáctica
Público objetivo: Estudiantes, docentes y monitores de estructuras de datos y algoritmos
Descripción general
El módulo de métodos de ordenamiento permitirá a los estudiantes comprender , ejecutar y visualizar
algoritmos clásicos de ordenamiento sobre arreglos de datos. El usuario podrá ingresar una lista de
valores, seleccionar un método de ordenamiento, ejecutar el algoritmo en modo rápido o paso a paso y
observar las comparaciones, intercambios, posiciones activas y estado final del arreglo.
Este módulo debe integrarse con la arquitectura general del visualizador y conservar las mismas
especificaciones de calidad, documentación, separación de capas, ayudas didácticas, trazabilidad,
pruebas y criterios de aceptación definidos para los módulos anteriores.
El proyecto general ya define una visión didáctica basada en visualización interactiva, interpretación
gráfica de código C, simulación paso a paso, retroalimentación inmediata y coherencia entre código,
visualización y estado.
Objetivo del módulo
Diseñar e implementar un módulo web didáctico que permita visualizar métodos de ordenamiento,
explicar su funcionamiento paso a paso, sincronizar la ejecución con código C/pseudocódigo y
comparar sus características principales.
Alcance inicial
La primera versión del módulo debe incluir:
Creación de un arreglo de valores.
Carga manual de valores por el usuario.
Generación opcional de arreglos aleatorios didácticos.
Validación de entradas numéricas.
Visualización del arreglo como barras, celdas o tarjetas.
Ejecución rápida del algoritmo seleccionado.
Ejecución paso a paso.
Resaltado de comparaciones.
Resaltado de intercambios.
Resaltado de posiciones ordenadas.
Conteo de comparaciones.
Conteo de intercambios o movimientos.

2. Visión del sistema
Problema que resuelve
Los métodos de ordenamiento suelen enseñarse con pseudocódigo o tablas estáticas. Sin una
visualización paso a paso, los estudiantes pueden tener dificultades para comprender comparaciones,
intercambios, pivotes, particiones, fusiones, subarreglos y condiciones de finalización.
El módulo busca transformar estos procesos en una experiencia visual donde cada paso del algoritmo
sea observable y comprensible.
Usuarios objetivo
Estudiantes de estructuras de datos.
Estudiantes de algoritmos.
Docentes de programación.
Monitores académicos.
Desarrolladores educativos.

5. Casos de uso
CU-O-001 — Acceder al módulo de ordenamiento
Actor: Estudiante
Descripción: El usuario ingresa al módulo de métodos de ordenamiento.
Precondiciones: La aplicación principal está disponible.
Flujo principal:
El usuario abre la página principal.
Selecciona “Métodos de ordenamiento”.
El sistema muestra la página principal del módulo.
El sistema muestra una explicación breve y controles iniciales.
Postcondición: El usuario puede crear un arreglo y seleccionar un algoritmo.
CU-O-002 — Crear arreglo manual
Actor: Estudiante
Descripción: El usuario ingresa manualmente los valores del arreglo.
Precondiciones: El usuario está en el módulo.
Flujo principal:
El usuario ingresa valores separados por coma o espacio.
El sistema valida los valores.
El sistema crea el arreglo en sesión.
El sistema muestra el arreglo en la visualización.
Flujo alternativo: Si hay valores inválidos, se muestra mensaje didáctico.
Postcondición: Existe un arreglo activo.
CU-O-003 — Generar arreglo aleatorio
Actor: Estudiante
Descripción: El usuario genera un arreglo aleatorio para práctica.
Precondiciones: El usuario está en el módulo.
Flujo principal:
El usuario define tamaño y rango de valores.
El sistema valida los parámetros.
El sistema genera el arreglo.
El sistema muestra el arreglo en pantalla.
Postcondición: Existe un arreglo activo generado por el sistema.

CU-O-004 — Seleccionar algoritmo
Actor: Estudiante
Descripción: El usuario selecciona un método de ordenamiento.
Precondiciones: Existe un arreglo activo.
Flujo principal:
El usuario abre la lista de algoritmos disponibles.

El sistema carga descripción, ayuda, código C o pseudocódigo.
El sistema habilita la ejecución.
Postcondición: Existe un algoritmo activo.
CU-O-005 — Ejecutar ordenamiento rápido
Actor: Estudiante
Descripción: El usuario ejecuta el algoritmo sin animación paso a paso.
Precondiciones: Existe arreglo y algoritmo activo.
Flujo principal:
El usuario presiona “Ejecutar”.
El sistema valida el estado.
El algoritmo se ejecuta.
El sistema muestra el arreglo ordenado.
El sistema muestra contadores y mensaje final.
Postcondición: El usuario visualiza el resultado final.
CU-O-006 — Ejecutar ordenamiento paso a paso
Actor: Estudiante
Descripción: El usuario ejecuta el algoritmo mediante traza interpretada.
Precondiciones: Existe arreglo y algoritmo activo.
Flujo principal:
El usuario activa “Interpretar paso a paso”.
Presiona “Ejecutar”.
El sistema genera la traza completa.
El sistema muestra el primer paso.
El usuario avanza o retrocede entre pasos.
El sistema sincroniza visualización, explicación y línea de código.
Postcondición: El usuario comprende el proceso completo.

- No poner lógica de negocio en JavaScript si debe estar en backend.
- No usar eval.
- No ignorar excepciones.
- No inventar algoritmos inexistentes en los archivos C.
- No eliminar archivos C originales.
- No acoplar la UI directamente a una función concreta del dominio.
- No compilar ni ejecutar C en servidor sin especificación adicional.
- No depender de detalles internos no documentados sin registrarlo como 
decisión técnica temporal.
